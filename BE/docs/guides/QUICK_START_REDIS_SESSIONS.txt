TL;DR - Get started in 2 minutes
================================================================================

DEVELOPMENT:

1. Install Redis locally:
   - macOS: brew install redis
   - Windows: Download from https://github.com/microsoftarchive/redis/releases
   - Linux: sudo apt-get install redis-server

2. Start Redis:
   - macOS/Linux: redis-server
   - Windows: redis-server.exe

3. Run the app:
   npm run dev

4. That's it! Sessions now persist in Redis

VERIFY IT'S WORKING:

1. Check startup logs for:
   "Session store: Redis"

2. Login and check Redis:
   redis-cli
   > keys sess:*
   Should show session keys like: sess:s1a2b3c4d5...

PRODUCTION:

1. Set REDIS_URL in environment:
   REDIS_URL=redis://:password@your-redis-host:6379

   OR set individual variables:
   REDIS_HOST=your-redis-host
   REDIS_PORT=6379
   REDIS_PASSWORD=your_password

2. Set strong SESSION_SECRET:
   SESSION_SECRET=<generate-32-char-random-string>

3. Deploy and run:
   NODE_ENV=production npm start

FAQ
================================================================================

Q: Do I need Redis for development?
A: No, it's optional. Without it, you'll see a warning but sessions work fine
   in memory. Just restart the server when switching sessions for testing.

Q: What's the performance impact?
A: Redis lookup is ~1ms. Totally acceptable and worth it for persistence.

Q: Can I run multiple servers?
A: Yes! That's the main benefit. All servers share sessions via Redis.

Q: What if Redis goes down?
A: App falls back to in-memory sessions with a warning. Not great for
   production, but better than crashing.

Q: How long do sessions last?
A: 24 hours by default. Change in app.js: cookie.maxAge property.

Q: Is this secure?
A: Yes! We added:
   - Secure cookies (HTTPS only in production)
   - HttpOnly flag (prevent JavaScript access)
   - SameSite=strict (CSRF protection)

Q: What about Docker?
A: Add Redis service to docker-compose.yml:
   services:
     redis:
       image: redis:latest
       ports: ["6379:6379"]

INTEGRATION WITH DEPLOYMENT
================================================================================

AWS DEPLOYMENT:
  - Use AWS ElastiCache for Redis
  - Set REDIS_URL to your ElastiCache endpoint
  - Ensure security group allows your app to access Redis

DOCKER DEPLOYMENT:
  - Add redis service to docker-compose.yml
  - Use redis://redis:6379 as REDIS_URL

KUBERNETES DEPLOYMENT:
  - Deploy Redis as separate pod or use managed Redis
  - Inject REDIS_URL via ConfigMap or Secret

HEROKU DEPLOYMENT:
  - Use Heroku Redis add-on: heroku addons:create heroku-redis:premium-0
  - REDIS_URL is automatically set
  - Just deploy!

MONITORING
================================================================================

Check Redis connection status:
  redis-cli ping

Monitor Redis keys:
  redis-cli --stat

Check session count:
  redis-cli eval "return #redis.call('keys', 'sess:*')" 0

Monitor memory usage:
  redis-cli info memory

Clear all sessions (development only):
  redis-cli FLUSHDB
